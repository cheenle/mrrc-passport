# 04. 系统上下文（APP 011）

## 4.1 系统与参与者

| 系统 / 参与者 | 在本记录边界内？ | 跨越边界的东西 |
| --- | --- | --- |
| 操作者 | 否（人） | 按键、旋钮旋转，以及面板给他们看的东西 |
| 终端固件 | **是** | 第 `05`–`15` 章的全部内容 |
| `mrrc_modern` 服务器 | 否（另一份记录） | 控制 JSON、双向 PCM16 音频、频谱帧、按键仲裁 |
| 电台（FT-710 及其它受支持机型） | 否（只能经服务器到达） | 没有任何直连：终端没有 CAT 链路 |
| 手机（配网） | 否 | 终端自己 SoftAP 上的一个 HTTP 表单 |
| 接入点 / 互联网 | 否 | 到 `w103d.vlsc.net:8888` 的 IPv6 路径（服务器仅 IPv6） |
| 电池 / 充电器 | 否（板级） | 电压、充电状态，进入电量指示 |

终端只有一个重要的网络对端（服务器），也只有一个重要的输入设备类别（按键）。它知道的一切都
经服务器到达，所以服务器的决策在本文档里只以依赖的形式出现（第 `08` 章 AD-004、§13.5）。

## 4.2 接口

| # | 接口 | 方向 | 协议 | 契约 | 所有者 |
| --- | --- | --- | --- | --- | --- |
| I-1 | 会话控制 | 终端 → 服务器 | WS 文本，JSON | `stateUpdate` 合并语义；终端绝不编造状态 | 共享，服务器权威 |
| I-2 | 接收音频 | 服务器 → 终端 | WS 二进制，通道 `0x00` | `[0x00][tag 0x02][int16 LE]`，16 kHz 单声道，20 ms 块 | 固件只负责播放 |
| I-3 | 发射音频 | 终端 → 服务器 | WS 二进制，通道 `0x01` | `[0x01][tag 0x02][int16 LE]`，每帧 641 B，写超时 100 ms | 固件（AD-004） |
| I-4 | 频谱 | 服务器 → 终端 | WS 二进制，通道 `0x02` | 每次电台扫描一帧；发射期间终端可降档丢弃 | 固件只接收 |
| I-5 | 按键仲裁 | 终端 ↔ 服务器 | WS JSON | 服务器决定；拒绝是可见的，绝不是无声载波 | 服务器 |
| I-6 | 配网 | 手机 → 终端 | SoftAP 上的 HTTP | 一个页面、SSID + 密码、保存后重启 | 固件（AD-006） |
| I-7 | 编解码器 | 固件 → ES8311 | I2S0（共享 MCLK/BCLK/WS）+ I2C | 两个方向都 16 kHz，只配置一次 | 固件（AD-003） |
| I-8 | 面板 | 固件 → ST7789 | SPI + LVGL port | 240×320，单块 24 行绘制缓冲，190 ms 刷新 | 固件 |
| I-9 | 电源 | 板级 → 固件 | ADC + 充电状态 | 百分比 + 充电标志，供电量指示 | 板级（BSP） |

## 4.3 网络拓扑与它的三个开关

服务器**只有 IPv6**可达，而 lwIP 默认不支持 IPv6。三件事必须同时成立（`../AGENTS.md` §2）
——两处配置、一处调用：

```c
CONFIG_LWIP_IPV6=y                    // 把 IPv6 编进 lwIP
CONFIG_LWIP_IPV6_AUTOCONFIG=y         // 接受路由通告（SLAAC）
esp_netif_create_ip6_linklocal(netif) // GOT_IP 之后调用它
```

只做前两件时，接口会永远显示 `0 IPv6 address(es)`，因为
`esp_netif_create_default_wifi_sta()` 自己不会挂 link-local 地址。这是两次域名切换失败的根因，
也是为什么终端的网络配置被写成一条三分量的事实，而不是一个设置项。

## 4.4 数据流

```
操作者 ──按键──▶ 终端 ──I-3 TX PCM16──▶ 服务器 ──CAT/音频──▶ 电台
                   ▲                        │
                   ├──I-2 RX PCM16──────────┤
                   ├──I-4 频谱──────────────┤
                   └──I-1 控制 JSON─────────┘

手机 ──I-6 SoftAP 上的 HTTP──▶ 终端（不涉及服务器）
```

这张图有三个承重性质：

1. **终端没有直通电台的路径**——它显示的任何电台行为，都是服务器先断言过的；
2. **配网是唯一不涉及服务器的流程**，所以它必须在完全没有网络时也能工作（AD-006）；
3. **音频与控制共用一条 TCP**，所以媒体阻塞与控制阻塞是同一次阻塞——这是 AD-004 的前提，
   也是"媒体拥塞绝不能被当成控制故障"的原因。
