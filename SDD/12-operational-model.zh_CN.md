# 12. 运行模型（ART 0522）

终端没有 shell、没有文件系统、现场也没有可见日志。所以下面每一个运行行为都写成带明确时间的
有序步骤，因为"它应该会重连"不是运行模型——**数字**才是操作者体验到的那个东西。

本章的所有时间参数都与源码核对过，且以源码为权威；若两者不一致，是本章错（第 `00` 章 §V7）。

## 12.1 启动顺序

| # | 步骤 | 仪器 | 失败表现 |
| --- | --- | --- | --- |
| 1 | `app_main` 启动，`mem_report("boot")` | `mem:` 行 | 复位循环——日志显示走到哪一步 |
| 2 | 从 NVS（`"mrrc"` namespace）载入设置，缺项回退 Kconfig | — | 缺键静默回退到编译默认值（AD-006） |
| 3 | 显示 + LVGL（`mem_report("display")`） | 面板点亮、chips 填充 | 面板黑；启动继续（坏面板不该拖垮音频路径） |
| 4 | 音频 + 编解码器 16 kHz（`mem_report("audio")`） | `i2s` 计数出现 | 之后发射被拒绝（第 `15` 章 §15.2） |
| 5 | 按键 + 按键任务（`mem_report("buttons")`） | 按下时记录日志 | 旋钮失效，其余正常 |
| 6 | 网络任务（`mem_report("net started")`） | `link:` 行 | 按 §12.3 的重试策略后转 UC-005 配网 |
| 7 | Wi-Fi 加入、IPv6 link-local、登录、`/WSterminal` | `ws: total=` | 见 §12.3 |
| 8 | 音频能力声明、首帧、播放 | 第一声 | 若档位被拒，保持连接并上报 |

`mem_report` 这些阶段存在的意义是：一个死在某一步的启动，能说出是哪个子系统吃掉了那块内存。
这也是内存回归可以被归因、而不是被猜出来的原因。

## 12.2 网络选择

1. 载入最多 **三个** (SSID, 密码) 组合：先 NVS，再 Kconfig，按顺序。
2. 优先上次可用的网络；若在范围内，直接加入并结束。
3. 否则扫描并给候选排序；排序只用信号强度**排名**，绝不用它判断质量（AD-007——那个
   −25 dBm 却在丢 10% 包的接入点）。
4. 在宣布网络不可用之前，**30 秒**后重试一次：只是重启中的路由器不该把设备推进配网模式。
5. 若加入失败两次，拉起 SoftAP（§12.4）。
6. 若已加入的网络不再产生健康的音频，切到下一个候选；一次切换要重新关联并重建会话，所以它
   必须是一个**决策**，不是一次**反应**（§12.6）。

## 12.3 会话建立与重连

| 情形 | 行为 | 时间 |
| --- | --- | --- |
| 登录失败 | 指数退避重试，有上限 | 从 **30 秒**起翻倍，上限 **600 秒**，成功即复位 |
| 登录成功但缓存 token 被拒 | "no control link with cached token" → 丢弃 token、重新登录 | 先给 socket **12 秒**再判定 |
| socket 自行掉线 | 让客户端自己重连 | 客户端重连 **500 ms** 加 TLS 握手（约 1.3 秒）；这就是发射失败后操作者听到的那段延迟 |
| socket 仍然不通 | 销毁并重建会话、重新登录 | 掉线满 **20 秒**后 |
| net 任务主循环 | 轮询状态、处理队列 | 每 **3 000 ms** |

固定的短重试会把终端永久停在服务器的登录限流里（每 IP 每五分钟 5 次），这就是退避从 30 秒
起、且随时间增长的原因。

## 12.4 配网

触发（任一条件）：

| 条件 | 原因 |
| --- | --- |
| 完全没有配置 SSID | 出厂状态 |
| 相差 30 秒的两次加入失败 | 操作者移动到了所有已存网络都不存在的地方 |

顺序：拉起 SoftAP `MRRC-Passport-XXXX` → DHCP 分发 `192.168.4.1` → 面板显示 SSID、密码与
URL → 手机连入并打开页面 → 提交表单 → 写 NVS → 重启进入 station 模式。

代价与它的预算：`esp_http_server` 多用 **+80 KB flash**，配网运行期间约 **15 KB 堆**——之所以
付得起，恰恰因为配网发生在 TLS 栈存在之前（配网模式下实测 `free=73K largest=64K`）。

保存失败时，`cfg_save()` 先打印 NVS 统计，再擦除分区并重试一次：配网是唯一可以安全擦除的时刻，
因为页面上的凭证本来就要取代里面的东西。这里静默失败与密码错误的后果无法区分，而设计拒绝这个
结果。

## 12.5 设置持久化

| 设置 | 何时写入 | 代价 |
| --- | --- | --- |
| 扬声器音量、麦克风增益、步进、滤波宽度 | 每次改动（旋钮） | 每档一次 NVS 提交；实测 `wr_max` 最高 **32 ms** |
| 服务器地址/密码、SSID | 仅配网 | — |
| 会话 token | 登录与失效时 | 每会话一次写入 |

那 32 ms 是 UI 路径上最大的单次停顿，且被接受：调档是人类速度的刻意动作。**不被接受**的是在
音频播放期间按定时器写盘——被持久化的集合恰好是操作者碰过的东西，别的都不写。

## 12.6 会话中途切换网络

1. 一次切换要求音频健康度**持续**劣化，不是丢一帧，也不是 RSSI 低。
2. 切换时：拆会话、重新加入、重新登录、强制 RX。
3. 迟滞是强制的：来回抖动的切换比一个差网络更糟，因为每次切换都要重新关联加一次登录。
4. 若所有候选都差，留在最不差的那个，并保持显示诚实——书面目标是优雅降级，不是连续性（AD-007）。

## 12.7 现场故障对照表

| 症状 | 第一台仪器 | 可能层次 | 动作 |
| --- | --- | --- | --- |
| 音频卡顿、`drop` 上升 | 先 `mem:` 再 `link:` | 设备队列 | 第 `08` 章 AD-001/AD-004 的地盘；不要先加大缓冲 |
| 按着键但 TX 指示熄灭 | 先 `tx done:` 再看 W/E 行 | 上行或会话 | 若 `sendfail>0` 且有 W/E 行，是 socket 在死（AD-004） |
| 没声音但显示在更新 | `i2s …/s` | 音频任务或环 | 区分环饿死与下行静默 |
| 完全没反应、面板黑 | `mem:` 启动阶段 | 供电或启动 | 最后一个是哪一步 `mem_report` |
| 连不上服务器 | `ws: total=`、IPv6 地址 | 网络（§4.3） | 三个 IPv6 开关 |
| 上机声音小、`peak` 低 | 发射行 `peak` | 电平（第 `15` 章 §15.4） | 提高 PGA 档位，绝不用服务器的软件增益 |

## 12.8 诊断节拍

- 每分钟一次：idle 行（`mem:`、`tx:`、`i2s`、`drop`），仅在 `CONFIG_MRRC_PROFILE=y` 时编入
  （guardian `diagnostics-not-shipped`）；
- 每次发射一次：`tx done:` 验收行（第 `15` 章 §15.5）；
- 按需：同一构建下的 `link:`、`ws:`、`txlink:`、`ring()`、`batt=` 行。

设备上没有持久日志。一次现场故障留下的证据，就是当时有人看着的那条 USB 串口行——这就是为什么
这些计数器被设计成"没有历史也够用"。

## 12.9 电源与电池

电量指示显示百分比，充电时变绿。没有优雅关机流程，也没有低电量禁止发射：设备要么有足够的电
发射，要么直接掉电，而发射中的掉电由电台自己的 TOT 收尾（第 `15` 章 §15.1）。这一条被记为
已接受的限制，不是疏忽。
