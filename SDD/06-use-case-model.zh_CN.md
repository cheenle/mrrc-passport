# 06. 用例模型（ART 0508）

## 6.1 参与者

| 参与者 | 描述 | 约束 |
| --- | --- | --- |
| 操作者 | 拿着终端、转旋钮、按 PTT | 只看得到面板；现场读不到日志 |
| 服务器（`mrrc_modern`） | 拥有会话、电台、按键仲裁，以及它发出的音频电平 | 可能在会话中途替换本终端；可以拒绝键控 |
| 手机（配网） | 连上终端的 SoftAP 并提交凭证 | 没有 App，只有浏览器 |
| 电台（经服务器） | 真正的收/发信机 | 它的 TOT 是最后一道有保证的停止手段 |

固件看不到电台，也看不到操作者的意图（除了按键）。以下每个用例都按这种"盲"来写：设备能证明
什么，必须假设什么。

## 6.2 核心用例

### UC-001：开机并到达会话

| 字段 | 描述 |
| --- | --- |
| 目标 | 上电后一次预缓冲内出声，不按任何键 |
| 前置条件 | 至少一个已配网络在范围内（或走 SoftAP 兜底，见 UC-005） |
| 基本流 | 启动 → 载入 NVS 设置 → 选网 → 关联 → 登录 → `/WSterminal` → 声明音频能力 → 首帧 → 播放 |
| 异常 | 无网络：SoftAP（UC-005）。登录被拒：保持连接、显示状态、按退避重试。之后会话掉线：重连并强制 RX（UC-003 异常） |
| 验证 | SC1；串口时间线；`ws: total=` 计数 |

### UC-002：收听

| 字段 | 描述 |
| --- | --- |
| 目标 | 只要在听，接收音频连续、显示诚实 |
| 前置条件 | 会话可用（UC-001） |
| 基本流 | 下行帧 → 环形缓冲 → 由 160 ms 预缓冲把关的播放 → 显示按 5.26 Hz 由真实频谱帧更新 |
| 异常 | 网络空档：预缓冲垫吸收；环干涸 200 ms 重建缓冲垫。长会话：0.16% 时钟漂移缓慢抽干缓冲垫——已接受并记录（AD-003） |
| 验证 | SC2、SC4；`underruns`、`rebuf`、`i2s …/s`、`drop` |

### UC-003：发射

| 字段 | 描述 |
| --- | --- |
| 目标 | 对方听得清；终端绝不把电台留在键控状态 |
| 前置条件 | 会话可用、编解码器在跑、服务器接受按键（第 `15` 章 §15.2） |
| 基本流 | 按下 → 前置条件 → 50 帧/秒 TX → 松开 → 单次释放写入 → 指示熄灭 |
| 异常 | 上行拥塞：100 ms 内写不出去的帧被丢掉，发射继续（AD-004）。发射中途会话死掉：重连、强制 RX、上报。服务器拒绝：指示不亮，原因写日志 |
| 验证 | SC3；`tx done:` 行的 `frames`、`sendfail`、`readfail`、`peak`；窗口内 W/E 行 0 条 |

### UC-004：用旋钮调频与改设置

| 字段 | 描述 |
| --- | --- |
| 目标 | 不用菜单就能改频率、模式、步进、滤波宽度、麦克风增益、音量 |
| 前置条件 | 凡是发给电台的都需要会话；STEP/FIL/MIC/VOL 是本地或索引类，**显示**不需要往返 |
| 基本流 | 旋转 → 档位变化以 OK 双击上报（AD-008）→ chip 本地立即更新 → 再发送；UP/DOWN 在 VFO 上纯调频 |
| 异常 | 滤波宽度只发**索引**，不发频率：服务器派生 Hz，设备只照抄（NFR-026）。链路慢只延迟回显，绝不延迟指示 |
| 验证 | chip 值与服务器状态对照；滤波三点核对（13→2400、17→2700、20→3000） |

### UC-005：给没有网络的终端配网

| 字段 | 描述 |
| --- | --- |
| 目标 | 什么都连不上的设备，用手机在两分钟内变得可用 |
| 前置条件 | 操作者能连上终端 SoftAP；终端已判定所存网络都不可用 |
| 基本流 | 触发 → SoftAP + 极简页面 → 手机提交 SSID/密码 → 写 NVS（AD-006）→ 重启或重新关联 → UC-001 |
| 异常 | 保存失败：页面必须说明，且旧凭证继续生效——这里静默失败与密码错误完全无法区分 |
| 验证 | SC6；NFR-012；`docs/provisioning.md` |

### UC-006：挺过网络变化

| 字段 | 描述 |
| --- | --- |
| 目标 | 操作者在网络之间移动时终端继续可用；链路差时降级而不是死亡 |
| 前置条件 | 最多 3 个已配网络（AD-007） |
| 基本流 | 开机给候选排序 → 连上次可用 → 音频健康度持续劣化则切换 → 重建会话 → 强制 RX |
| 异常 | 全部网络都差：留在最不差的那个、继续重试、显示保持诚实。抖动：迟滞必须阻止来回切，因为一次切换要重新关联 |
| 验证 | SC7；NFR-008、NFR-010；火车上手机热点那一轮（丢包 6.5–12%，RTT 峰值 6–10 秒） |

### UC-007：在台面上诊断故障

| 字段 | 描述 |
| --- | --- |
| 目标 | 用一条 USB 串口线区分链路、设备、服务器三类故障 |
| 前置条件 | 打开 profile 的构建（`CONFIG_MRRC_PROFILE=y`，刻意不进出货） |
| 基本流 | 读 idle 行（`mem`、`tx`、`i2s`、`drop`）→ 读 `link:`/`ws:`/`txlink:` → 与服务器 `TX session` 行对照 → 与参考客户端对照 |
| 异常 | 只有一台仪器：那么结论只是观察，不是证据（第 `00` 章 §V2） |
| 验证 | SC8；第 `00` 章 §0.3 |
