# UI 布局与样式

MRRC Passport 屏幕（240×320，ST7789，圆角面板）的当前实现说明。
所有坐标、字号、颜色均与 `main/mrrc_ui.c` 一致；改代码时请同步本文。

---

## 1. 画布与刷新

| 项 | 值 | 说明 |
|---|---|---|
| 分辨率 | 240 × 320 | 竖屏 |
| 颜色格式 | RGB565 | `LV_COLOR_FORMAT_RGB565` |
| 刷新周期 | `REFRESH_MS = 190`（5.26 Hz） | 见下方说明 |
| LVGL 绘制缓冲 | 24 行（11.3 KB） | `BSP_LVGL_DRAW_BUFFER_LINES` |
| 双缓冲 | 关 | 内存不够；渲染与 SPI 串行 |

**刷新率为什么是 5.26 Hz**：与电台自身的扫描率对齐，所以每一行瀑布都是实测
数据而不是插值。代价是 CPU：`taskLVGL` 从 300 ms 档的 23% 升到 33–42%。
200 ms 早期试过、过于激进——`taskLVGL` 占 47–55%，音频任务（每 20 ms 要喂一次
阻塞式 I2S 写）只拿到 <1%，环形缓冲溢出导致 RX 断续。

## 2. 配色

**所有颜色常量是 24 位 `0xRRGGBB`，不是 RGB565。** 它们交给
`lv_color_hex()` 在运行时转换。

> ⚠️ 历史坑：曾把手持机 `ui.c` 里的 RGB565 字面量直接抄过来喂给
> `lv_color_hex()`，被当成 RGB24 的低 16 位解释，整张调色板偏移 ——
> `0xFFFF`（白）变成 `0x00FFFF`（青），`0x3C1E`（蓝）变成 `0x003C1E`（暗绿）。

| 宏 | 值 | 用途 |
|---|---|---|
| `C_BAR` | `0x2A2A2A` | 顶/底 chrome 条底色 |
| `C_ORANGE` | `0xFFA500` | 分隔线、顶/底行文字 |
| `C_FIELD` | `0x3A3A3A` | 字段底板（亮） |
| `C_FIELD_D` | `0x212121` | 字段底板（暗） |
| `C_ACCENT` | `0xE87A00` | S 表指示条 |
| `C_FAINT` | `0x6B4A00` | 极淡的标记 |
| `C_TEXT` | `0xFFFFFF` | 主文字（频率等） |
| `C_RED` | `0xFF0000` | TX 状态 |
| `C_GREEN` | `0x00FF00` | 充电、信号“良好”档 |
| `C_BLUE` | `0x3B82F6` | 频谱曲线 |

## 3. 纵向布局

```
y=  0  ┌────────────────────────────────┐
       │ 26 px chrome 条（含文字，y=8）   │
y= 26  ├────────────────────────────────┤ ← 橙色分隔线（rule）
y= 46  │        7.079.51   ← 44 px 白字 │
y=102  │ [40m] [FL 2.4K] [SPK 60%] [200K]│  ← 12 px
y=121  │ [S 9+20][██████████░░░░░░░░░░]  │  ← S 表，独占一行
       │         （5 行黑隙）             │
y=146  │  ╱╲    ╱╲╱╲    ╱╲    ← 频谱曲线 │  PLOT_H=45
y=191  │        （5 行黑隙）              │
y=196  │ ▒▓█ Jet 瀑布，40 行              │  WF_H=40
y=236  │                                 │
y=254  │ [7.029]     [7.079]     [7.129] │  ← 刻度
y=270  ├────────────────────────────────┤ ← 橙色分隔线（rule_bot）
y=272  │ FREQ          RX          LINK  │  ← chips 条
y=294  └────────────────────────────────┘
```

### 常量表

| 宏 | 值 | 内容 |
|---|---|---|
| `SCR_W` / `SCR_H` | 240 / 320 | |
| `H_HDR` | 26 | 顶栏高度 |
| `Y_FREQ` | 46 | 频率 |
| `Y_INFO` | 102 | 第 1 行：波段 / FL / SPK / SPAN |
| `H_INFO` | 17 | |
| `Y_SMET` | 121 | 第 2 行：S 表 |
| `H_SMET` | 18 | |
| `Y_PLOT` | 146 | 频谱曲线起点 |
| `PLOT_H` | 45 | 曲线高度 |
| `Y_WF` | 196 | 瀑布起点 |
| `WF_H` | 40 | 瀑布行数（18.8 KB `.bss`） |
| `Y_SCALE` | 254 | 刻度行 |
| `Y_CHIPS` | 272 | 底部状态条 |
| `H_CHIPS` | 22 | |

### 为什么频谱与瀑布之间留 5 行黑隙

`Y_PLOT + PLOT_H = 191`，`Y_WF = 196`。LVGL 会把**相邻的脏区合并**：
瀑布紧贴曲线时，两者被当成 146..232 一整块重绘（约 40 KB），
留空隙后各自独立重绘。

实测收益：`taskLVGL` 44% → 35%。不是决定性改善，但方向正确。

## 4. 字体

只有 **2 套** Montserrat 被编译：**12** 和 **44**（默认字体为 12）。

对应配置（`sdkconfig.defaults` 与构建机的 `sdkconfig` 都要一致）：

```
CONFIG_LV_FONT_MONTSERRAT_12=y
CONFIG_LV_FONT_MONTSERRAT_44=y
CONFIG_LV_FONT_DEFAULT_MONTSERRAT_12=y
```

> 曾编过 12/14/20/28/44 五套。14 与 28 在改用 12/44 后再无引用；
> 20 从未被使用过。多余的每套是几 KB flash —— 不影响 `largest`（字模在 flash），
> 但没必要留着。

| 用途 | 字号 | 备注 |
|---|---|---|
| 顶栏（模式 / VFO / 电量） | 12 | 橙色 |
| **频率** | **44** | 白色，原生字模 |
| 第 1 行四块底板 | 12 | |
| S 表数字 | 12 | |
| 刻度行 | 12 | |
| 底部 chips | 12 | 橙色 |
| 瀑布「SPAN」标签 | — | 已移除 |

### 频率为什么用原生 44 号，而不是缩放

曾经用 `lv_obj_set_style_transform_scale(s_freq, 384, 0)` 把 28 px 放大 1.5×，
结果是：

- `transform_scale` **不会放大对象本身**，42 px 的字形画进 28 px 的框 → 只剩上半截
- 把框改高 → **完全黑屏**（与这块屏的圆角遮罩回调 `rounded_flush_event` 冲突）

改用原生 44 px 字模，稳定清晰。相关设置：

```c
lv_obj_set_width(s_freq, SCR_W);
lv_obj_set_height(s_freq, 52);          /* 字面行高，否则下伸部被裁 */
lv_obj_set_style_text_align(s_freq, LV_TEXT_ALIGN_CENTER, 0);
lv_obj_align(s_freq, LV_ALIGN_TOP_MID, 0, Y_FREQ);
```

**注意顺序**：先设尺寸再 `lv_obj_align`，否则锚点按旧尺寸算。

## 5. 各区块细节

### 5.1 顶栏（y=8，橙色 12 px）

| 元素 | x | 内容 |
|---|---|---|
| `s_mode` | 8 | `LSB` / `USB` … 电台模式 |
| `s_vfo` | 172 | `VFO A` |
| RSSI 四根竖条 | 158 起 | 3 px 宽、5 px 间距、底边对齐 y=20 |
| `s_batt` | 196 | `87%` |

**RSSI 是矩形，不是文字**：用 4 个 `lv_obj`，高度递增（4/7/10/13 px），
底边对齐。亮的白色、暗的 `C_FIELD` 灰。

> 曾用 `▂▄▆█` 字形，但字体基线不一致，看起来不像表；也曾用彩色，
> 让状态图标像报警。现在统一白色。

### 5.2 频率（y=46）

Montserrat 44，白色，水平居中。格式 `7.079.51`（`format_freq`）。

### 5.3 第 1 行（y=102，四块底板，12 px）

| 元素 | x | 宽 | 内容 |
|---|---|---|---|
| `s_bandplate` | 2 | 52 | 波段名 / 频道名 / 音量（随旋钮模式） |
| `s_fil` | 57 | 58 | `FL 2.4K` |
| `s_af` | 118 | 62 | `SPK 60%` |
| `s_spanplate` | 183 | 55 | `200K`（实际 span） |

总宽 238 / 240 px，无重叠。

> **宽度教训**：`FIL 2.4K` 在 14 px 下要 ~62 px，底板只给 56 px 时会**折行**，
> 第二行正好压在 S 表上。降到 12 px 后 `FL 2.4K` 约 55 px 才放得下。

`s_bandplate` 内容随旋钮模式变化：

| 模式 | 显示 |
|---|---|
| FREQ | 波段名（如 `40m`） |
| CHANNEL | 频道名 |
| VOL | 音量百分比 |

### 5.4 S 表（y=121，独占一行）

- `s_sunit`：x=2，宽 52，`S 9+20` 文本（12 px）
- `s_sbar`：x=62，宽 `SCR_W-66`，高 `H_SMET-4`，范围 0..255，指示条 `C_ACCENT`

> 用户明确要求「S 表单独一行，数字和条形在同一行」。

### 5.5 频谱曲线（y=146，高 45）

`lv_line`，`C_BLUE`（TX 时 `C_RED`），线宽 3，圆角接头。

> 圆角很重要：butt cap 下 LVGL 的抗锯齿线段在陡变处留空隙，看起来像**一排点**。
> 这版 LVGL 没有独立 cap 样式，`line_rounded` 同时开圆角和端点。

数据来源：850 bins 峰值降采样到 240 列（**取峰值不取平均**，平均会藏掉窄信号）。
映射固定 `SCOPE_FLOOR=71` / `SCOPE_CEIL=233`（不做自适应 AGC，否则单个载波出现时整条曲线跳）。

### 5.6 瀑布（y=196，40 行）

`lv_canvas` + RGB565 缓冲（`240×40×2 = 18.8 KB` 静态 `.bss`）。

- **最新一行在顶部**，历史向下滚（与手持机的环形缓冲一致）
- 每来一个真实扫描帧推 1 行（**不做插值**）
- Jet 调色板，64 级，`idx 0` 是深蓝不是纯黑（纯黑看起来像"没数据"）

> 曾试 60 行：把 `largest` 压到 3 KB，PTT 的 TLS 握手拿不到连续内存 → 发射自己断。
> 40 行 = 18.8 KB，是当前的平衡点。

### 5.7 刻度行（y=254）

三个底板：x=2 / 92 / 184，宽 54 / 56 / 54，显示 `VFO-span/2`、`VFO`、`VFO+span/2`。

### 5.8 底部 chips（y=272，橙色 12 px）

三个固定槽位（避免定位方式打架）：

| 元素 | x | 宽 | 对齐 | 内容 |
|---|---|---|---|---|
| `s_chip_mode` | 8 | 44 | 左 | `FREQ` / `CH` / `VOL` |
| `s_chip_tx` | 96 | 48 | 居中 | `RX` / `TX` / `TXT`（红） |
| `s_chip_link` | 188 | 52 | 右 | `LINK` / `noSRV`（红） |

> 曾混用绝对 x 与 `LV_ALIGN_TOP_MID`，模式文字和 RX/TX 文字抢同一位置。

### 5.9 分隔线

两条 1 px 橙色横线：

- `rule`：y=`H_HDR`(26)，顶栏下方
- `rule_bot`：y=`Y_CHIPS-2`(270)，chips 条上方

## 6. 圆角面板

屏幕四角是圆的，`rounded_flush_event`（`bsp_display_lvgl.c`）在
`LV_EVENT_FLUSH_START` 时把圆角外的像素刷黑。

后果：**y=0 附近的字形会被裁掉**。所以顶栏文字下移到 y=8。
`bsp_display_rounded_row_span()` 对中间行直接返回全宽，只有边缘行做计算。

---

## 7. 旋钮模式与提示

OK 双击循环 `FREQ → CHANNEL → VOL → FREQ`，只在底部 chips 的
`s_chip_mode` 显示一处。

> 曾有橙色 toast 同时显示模式，两条写入路径不同步，切模式后一帧内会看到矛盾。
> toast 已移除（`mrrc_ui_set_toast()` 保留为空函数）。

## 8. 频谱档位（服务端协商）

连接时发 `{"type":"spectrumCaps","profile":"high"}`。

| 档位 | 帧大小 | divider | 帧率 | 带宽 |
|---|---|---|---|---|
| `high`（Full） | 1701 B | 1 | ~5.3 帧/秒 | ~73 kbit/s |
| `mid` | 851 B | 2 | ~2.7 帧/秒 | ~18 kbit/s |
| `low` | 426 B | 4 | ~1.3 帧/秒 | ~5 kbit/s |

接收用 `high`，**发射时切到 `low`**（发射时屏幕没人看，省带宽给音频上行）。

> 早期固件写死 `mid`，瀑布看起来像爬 —— 每帧就是一行的历史，半速就是半行速。

---

## 9. 改动 UI 时的检查清单

1. **改颜色**：确认传给 `lv_color_hex()` 的是 24 位值，不是 RGB565
2. **改字宽**：算清底板总宽 ≤ 240，留 ≥ 2 px 余量，否则会折行压到下一行
3. **改纵向坐标**：确认与相邻区块不重叠，且频谱/瀑布之间保留空隙
4. **改瀑布行数**：`WF_H × 240 × 2` 是 `.bss` 占用，同时看 `largest` 是否仍 > 30 KB
5. **加字号**：每套 Montserrat 是几 KB flash（不在堆上），但要同步 `sdkconfig` 和 `sdkconfig.defaults`
6. **改刷新率**：越高 LVGL 越吃 CPU，直接影响音频断续
7. **不要用 `transform_scale`**：这块屏上会裁切或黑屏
