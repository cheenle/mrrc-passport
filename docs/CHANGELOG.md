## Unreleased

## v1.3.0 - 2026-11-23

- Transmitting no longer tears the connection down. The server kept writing the
  radio's RX audio to the terminal socket while it was keyed — 30 KB/s down
  against 32 KB/s up on one TCP — so on a mobile link the uplink write blocked for
  a second, the websocket client treated that as fatal and reconnected, and the
  operator saw "PTT released by itself" with the key still held. A keyed socket
  now gets no downlink audio (half duplex: it cannot hear), and the uplink send
  timeout drops 500 -> 100 ms so a congested frame costs one frame instead of
  half a second. Measured: 1500 frames / `sendfail=0` in a 30.5 s transmission,
  50.0 frames/s, worst send 27.9 ms.
- Set the device up with no network of any kind: when there are no credentials, or
  two connection attempts fail, the terminal raises its own access point
  (DHCP 192.168.4.1, one page with Wi-Fi and server fields) and reboots into
  station mode with what the phone submitted. Settings live in NVS and override
  the Kconfig defaults, so a provisioned unit never needs a rebuild; a failed
  save erases and retries once, because the Wi-Fi driver's per-boot NVS writes
  eventually fill the 24 KB partition.
- Two knob families instead of one cycle: OK double-tap walks the local pair
  (VOL <-> MIC), UP/DOWN double-tap walks the radio group
  (FREQ -> CH -> STEP -> FIL). Each keeps its own position. The arrow-key window
  is 450 ms measured, and the first press's step is undone so changing modes never
  nudges the frequency.
- New STEP (1K/5K/25K) and FIL (1.8K/2.4K/2.7K/3.0K) positions, persisted in NVS;
  the filter width is pushed to the server and re-sent once the link comes up.
- Panel: the scale row lost its plates and hugs the screen edges, the chips bar
  moved down to the bottom edge, and the waterfall gained a 1 px red centre
  cursor.

- Cut the UI's CPU share by a third without touching the layout. `refresh()`
  rewrote the frequency and info-row labels whenever the state sequence moved,
  and `lv_label_set_text()` invalidates even when the string is identical; those
  two regions were 40% of every repaint. Labels are now compared before being
  set: flush volume 526 → 344 KB/s, `taskLVGL` 56–61% → 43%, IDLE 7–14% → 28%.
  Two instruments were added behind `CONFIG_MRRC_PROFILE` to find this —
  `bsp_display_flush_stats()` (bytes/screens per second) and
  `bsp_display_flush_bands()` (the same pixels per 32-row band).
- Draw the spectrum trace with one vertex every 2 columns instead of per column.
  Control experiments put the trace at 25 CPU points while it covers only a
  quarter of the flushed area — LVGL pays per anti-aliased segment, not per pixel.
  `taskLVGL` 42% → 28–30%, IDLE 29% → 42–45%, with the same line weight and the
  same repaint volume.
- Instrument the WebSocket handler per payload kind: audio 70 µs per message,
  spectrum 53 µs, control JSON 897 µs — our handler is ~1.1% of the CPU, and the
  rest of `websocket_task`'s 15% is TLS and frame reassembly inside
  `esp_websocket_client`.
- Store the waterfall as 8-bit palette indices instead of RGB565: the largest
  single `.bss` block drops from 19,200 B to 10,624 B, steady-state `free` goes
  48 → 57–59 KB and `largest` 27–42 → 38–48 KB, for 1–2 CPU points of palette
  lookup while blending.
- Stop losing 2% of downlink frames to lock contention: `rb_put()` took the ring
  mutex with a zero timeout, so every overlap with the consumer's copy discarded a
  frame. A 2 ms timeout (100x the hold time, far below one frame period) leaves
  only burst overruns, which are now minutes apart instead of continuous.
- Survive a mobile link (measured on a train: 6-12% loss, RTT peaks of 6-10 s).
  A stall longer than a second now discards the queued audio and re-buffers
  instead of replaying it stale, and when the ring passes 75% the oldest frames
  are dropped rather than the newest, so a recovery burst leaves fresh audio
  behind. On that link: drops +200/min → 0, `i2s` 1.9-26 → 26-47 frames/s.
- Keep up to three Wi-Fi networks and choose between them: at boot the firmware
  scans and connects to the strongest configured SSID it can see (falling back to
  the first, so single-network setups are unchanged), moves on after three failed
  connections, and switches on audio health alone — two consecutive minutes over
  2% drops or 50 underruns/s triggers a rescan, because a hotspot can deliver that
  while `esp_wifi` still reports the link as up. Same train, AP changed from
  `cnham-MM` to an iPhone hotspot: drops +200/min → 0, frames written 1.9-26 → 44-47/s.
- The design record is now published next to the product: thirteen chapters of
  `SDD/` (what the device must do as measurable numbers, why it is built this way
  with the rejected alternatives, and the incident ledger including what was *not*
  fixed), rendered at
  https://www.vlsc.net/mrrc_modern/sdd-passport/ , plus a printable one-page
  <a href="https://www.vlsc.net/mrrc_modern/passport-field-card.html">field card</a>
  with the transmit acceptance values and the symptom-to-instrument table. The
  numbers on the card are checked against the record by CI, so the two cannot drift.

## v1.2.1 - 2026-11-21

- Remove the stutter in both directions. Five independent causes, each measured
  on the board and on the server:
  - the downlink was limited by the terminal's receive queues, not the link —
    `TCP_RECVMBOX_SIZE` 6, `TCP_OOSEQ_MAX_PBUFS` 4 and `RX_BA_WIN` 6 were what
    filled first, not the TCP window; the device now receives 49 KB/s with the
    same client-visible rate as a reference client on the same Wi-Fi;
  - playback started from an empty ring, so every network gap starved the DMA —
    it now pre-buffers 160 ms and re-buffers after 200 ms dry;
  - the server's `max pump stall` fell from 5791 ms to 3 ms;
  - the uplink ran with Nagle and a four-MSS send buffer: 31% of audio sends
    blocked over 30 ms, worst 89 ms. `tools/patch_ws_nodelay.sh` sets
    TCP_NODELAY and `TCP_SND_BUF_DEFAULT` doubles; sends now block at most
    9–17 ms and the server reports `queue_drops=0` on every session;
  - transmit audio was clipping 5% of samples because the device's analog PGA
    (+30 dB) and the server's software gain (+12 dB) stacked. The software gain
    was an identity operation with a headroom cost; at 0 dB a full transmission
    adds zero clipped samples.
  See [transport tuning](transport-tuning.md) for the measurements.

- Make the firmware gate work again. `tools/verify_firmware.py` still demanded an
  image called `FoloToy-AI-Passport.bin` after the project was renamed to
  `mrrc-terminal`, so every firmware check — and with it every tag release since
  1.0.0 — failed with `flash_args is missing required images`. The application
  image is now derived from `flash_args`, and `tools/archive_firmware.py` does the
  same.

- Every Markdown file now has an English default and a `.zh_CN` peer as the
  repository rule requires; `./tools/validate.sh --static` exits 0 for the first
  time, with the host tests reported as skipped because this fork does not vendor
  the upstream `tests/` tree.

## v1.2.0 - 2026-11-20

- Releases are source-only from now on: the tag workflow still builds and verifies the image as a gate, but it publishes no firmware artifact, and the GitHub Release carries only the automatically attached source archives. A CI image cannot hold this terminal's credentials, so a prebuilt image would boot and never reach the radio.

- Stop losing downlink audio frames: the 8 KB PCM ring becomes 16 KB (0.26 s -> 0.51 s) so the TCP backlog at session start has somewhere to land, the WebSocket receive buffer goes 4 KB -> 8 KB so a 1701-byte spectrum frame no longer back-pressures the socket (the server measured a 5.8 s pump stall), and the link is now half duplex — the spectrum tier drops to `low` and scope frames are discarded while keyed. Measured on the live server by the author: `err=0 drop=0` at 49.9 frames/s. On our bench unit the same build still loses ~2%, so a second cause remains open.

- Add `probe/`, the throwaway bring-up firmware for the next-generation touch handheld (ILI9341 + FT6336G + ES8311), with its design document. It is a separate ESP-IDF project under `probe/` and is not part of the `mrrc-terminal` image.

- Make a clean checkout build and fit on the board: restore `CONFIG_LV_FONT_MONTSERRAT_44` (the frequency readout uses that face and `sdkconfig.defaults` no longer enabled it, so a fresh clone did not compile), turn off `CONFIG_LV_ATTRIBUTE_FAST_MEM_USE_IRAM` (with the `^9.5.0` constraint resolving to LVGL 9.6 it moved ~117 KB of code into SRAM, leaving an 88 KB boot heap and an `esp_wifi_init` out-of-memory reboot loop), and split the defaults so per-device credentials live in a gitignored `sdkconfig.defaults.local` instead of the public tree.

- Added the supplied 80-byte CW2017 profile for the specified 520 mAh cell, including content/update-flag checks, verified writes, the required restart sequence, and bounded SOC-readiness polling.

- Expanded the environment bootstrap document: added Espressif's Git service mirror (`git.espressif.com.cn`) as the preferred mainland-China route for ESP-IDF v5.5.3 and its submodules, documented submodule long-wait/timeout handling, in-place repair, and the pinned-commit shallow fetch for large submodules such as `esp32-wifi-lib`, warned about stale per-repository Jihulab `insteadOf` residue, and added the official offline release archive as a last-resort fallback (learned from `esp-mosaico/esp-mosaico-vibe`).
